# H3 电影视听制作

把导演意图落实为可播放的电影：先定视角、情绪和信息释放，再写英文视听时间轴，最后使用真实参考素材生成并审验。用户只要提示词时交付提示词；用户要影片时，提示词、运行中的任务或 HTTP 200 都不算成片。

本技能适配用户已安装的 H3 技能及其来源《H3电影级提示词-SKILL-V1.0.docx》，必要方法和引用均随本包携带，不依赖个人技能目录。六段式、声音 ID 与对白容器是经验组织方法，不是模型硬 schema 或质量保证；来源与边界见[来源说明](references/source-and-scope.md)。

## 资源与执行边界

先识别实际模型与资源来源。用户已授权的既有 PPU 自部署 H3 和固定制作范围直接沿用，不因 `cost:unknown` 反复询价，也不宣称零成本或无限额度。新增第三方收费、扩容或实质范围变化才补确认；既有授权、Host 范围卡与实际额度分别保留。

平台内真实生成只走本会话声明的 `easel_video_generation`，工程登记与交付走 `easel_workshop_delivery`。先看 `catalog`，按真实计划批准后执行；不以本地清单或默认答案自授权限。执行参考中的供应商 HTTP 形状仅供适配理解，不授权 Native AI 用 shell、SDK 或浏览器绕过 Host 发请求、读取密钥、重启或另开资源。

## 根据任务读材料

- 构思、分镜、镜头与光声设计：读 [导演与连续性](references/directing.md)。
- 编译提示词、对白、声音与参考素材：读 [提示词语法与范例](references/prompt-grammar.md)。
- 实际生成、状态、收取和交付：读 [Ref2VA 执行与验收](references/ref2va-execution.md)，以 Host `catalog` 与回执核对能力；供应商服务快照不能替代本次检查。

## 工作流程

1. 从用户已有材料恢复主题、总时长、画幅、角色、对白、参考素材及已批准的生成范围。缺少非关键选项时做合理选择并记录，不因一般创作选择反复打断。用户指定 H3/PPU 时保持该选择；其他技能的默认视频供应商不能覆盖它。
2. 为每段确定视角、情绪变化和一项主要戏剧功能。按动作完整性与情绪单元切段，镜数和总片长服从任务，不硬套四段、固定镜数或固定时长。先用一段验证角色、质感、对白与声音，再展开后续镜头。
3. 建立镜头计划和连续性账本：固定角色描述、服装道具、空间轴线、光位色温、声音 ID 与环境底噪。每镜写清景别、机位、透视/景深、人物调度、运镜与同步声音。
4. 将构思编译为英文六段式视听描述，中文只保留在 `<d>[Chinese] 原词 </d>` 对白容器内。为发声人物固定 `(S1)`、`(S2)` 等 ID，动作与说话方式放在容器外；实际参考按本段各模态局部 `Image 1 / Video 1 / Audio 1` 编号映射。基础三字段与六段式都是 **`prompt` 字符串中的文本结构**，不是 Host 或供应商的 JSON 参数；不能用未上传的标签或本地文件名代替映射。
5. 执行前核对时长、参考数量、模型、音频与画幅等真实接口约束。当前 Ref11 需要图片或视频参考；没有素材时，先在任务授权范围内准备角色/场景参考，不能用空参考请求冒充纯文生视频。
6. 每次通过 Host 提交后保存原任务 ID、输入摘要和素材清单。未知只查原任务，不换 ID 重投。按真实批准的片段与返修额度运行；未获准的返修不自动新增请求。需要修改已冻结范围时，先收取并保留原任务证据，再按 Host 已支持的受控替换契约取得新范围，不手改批准或回收 claim。
7. 长片按片段验收再承接。需要状态承接时，可将本镜成片出点最后可见帧作为下一段的 **软参考**，按需要搭配角色锚点；不强制每段同时喂尾帧和锚点，也不能用被剪掉的原始尾帧代替。若多图出现不期望的蒙太奇或画面重放，可减为一张能承载目标镜头的人物场景参考，以明确的编辑切接承接。软参考不保证第 0 帧精确对齐，减图也不保证消除问题；比较实际边界帧并记录修补。
8. 下载原始 MP4，检查画面、声音、对白、切点与连续性。保留模型原生音轨；拼接需要处理爆音、音量突变或音乐断裂时另存后期版并记录操作。不要用替换配音掩盖原生音画未通过。

## 完成标准

交付与请求规模相称的成片、原始片段、镜头计划、提示词、连续性账本、运行清单和可复验的 QA 记录。清单包含模型、实际请求参数、参考素材来源、任务 ID、生成时间、下载状态与成片 SHA256；不含令牌或私钥。可用 FFmpeg/ffprobe 检查媒体，仍需实际看片与听音。

核对人物/服装/道具、动作与空间、情绪与镜头意图、对白原文及声音 ID、音画对齐、字幕水印和切点。报告实际通过的范围和仍存在的问题。8 NFE Ref11 是当前实验蒸馏部署，不能把一次范例或既往 SHA 一致性结果解释为所有输入的质量无损保证。

用户已经直接听出原词、说话人或音色不符时，记下该项失败，不反复要求其证明同一事实。保留源片与后期版分别核对；具体根因未证实时保持未定，不能仅凭 8 NFE、WAV 输入或提示词格式推定因果。实际成片仍须看片、听音，不能靠字段齐全或 ASR 分数自动认证。
