# AI 短剧带货

把有依据的购买理由写进人物行动，交付可播放的剧情带货样片及可复用工程。用户只要方案时交付策划；用户要视频时，剧本、参考图和运行中任务都不是成片。

## 输入与模式

- 接受商品链接、SKU、产品图／视频、品牌资料、目标人群、平台、时长、画幅、风格、条数及预算。商品未指定且用户允许代选时，选择事实和素材容易核实的小商品。
- 读取已有画像、创作简报、工程和用户已确认的资源与范围；不重复索要已有资料。普通创作选择可合理决定并记录。真实制作前的画幅和费用条件沿用本次用户已接受的方案。
- `plan`：商品事实卡、创作简报、剧情方向、剧本、分镜与资源计划。
- `produce`：在已授权制作范围内制作视频、字幕、封面和发布素材，完成检查。
- `revise`：从当前工程修订指定镜头或文案，保护已采用素材及人工调整。
- `analyze`：使用真实平台／商家数据复盘；无数据时只列待采集项。

## 工作流程

1. **商品事实**：按 [商品与输入输出](references/product-and-brief.md) 建立事实卡，固定 SKU、规格、适用条件、来源和核对时间。区分已核实、品牌自述、待补信息；台词与画面中的功能、数据和优惠要能回指来源。没有证据的销量、认证、评价、效果不编写。
2. **品类与故事**：按 [品类与剧情](references/category-playbooks.md) 选择购买动机与展示方式。写清人物想完成的具体任务、阻碍、商品如何参与行动、结果和购买顾虑。角色完成情绪转变，商品解决具体任务。一般先给少量不同方向，实际生成数量服从用户任务。
3. **冻结简报与分镜**：按本次任务确定时长与镜数，不硬套固定秒数。每段写景别、调度、对白说话人、商品状态、参考映射和出点。商品出场既要符合因果，也要让观众理解购买理由。单片和系列分别保留角色、场景与道具的连续性。
4. **核对真实运行能力**：读取当前模型／服务／CLI 能力，核对参考模态、时长、画幅、原生音频与资源状态。配置存在、网关健康和历史样片不等于本次推理可用。用户指定的模型、机器及保持停止的服务状态优先；不擅自更改其他任务或服务。
5. **资源与范围**：已有授权覆盖的自部署 PPU 和固定制作范围直接沿用，不因未知报价反复询价，也不宣称零成本。新增第三方收费、账户或实质范围增加时，先准备具体方案和可核对费用，再取得所需授权。
6. **参考与动态生成**：用真实商品图锁定外观，用角色／场景图锁定身份。默认先验证一段，再展开后续；明确独立的片段可在资源允许且用户范围覆盖时并行。调用实际可用的运行适配器，记录输入摘要、模型、任务 ID、原生参数及状态；不猜 API。已部署的外部 CLI 与站内 Host 各按自己的访问契约操作，不伪造人工批准。
7. **保真与声音**：遵循 [制作与验收](references/production-and-acceptance.md)。剧情镜头必须有真实动作；静态商品信息卡可以作为明确的尾卡，不能填充成动态剧情。商品特写优先真实素材；AI 使用情境是演绎，不是实物测试证据。保留原声并核对台词、说话人和口型。
8. **后期与返修**：按完整动作和对白选择切点，后加可读字幕；默认白字细描边，可按品牌调整。控制配乐不压对白。依据实际问题局部返修，不用冻结、循环、过度慢放或替换配音掩盖未通过的生成段。保留源片与后期版。
9. **真实交付**：量测实际时长、画幅、音视频流、完整解码和 SHA256，观察画面与切点，核对声音与字幕。ASR 是辅助证据，不能替代听音或自动证明表演合格。未检查或未通过项如实列出。接入工坊时，绑定真实工程、渲染来源版本和具体成片，自动预审不冒充人工审批。
10. **发布准备与复盘**：按当前平台核对 AI 标识、虚构演绎及广告可识别性，分别记录；核实商品挂载能力、目标 SKU 和发布回读。用户只要求预览时止于交付。成交／退款／佣金数据只从真实来源读取，不把播放或点赞推断为成交。

## 断点与结果未知

- 先读取本项目状态，再决定是否提交；不覆盖人工修改或既有成片。
- 请求结果未知时保留原任务、操作 ID 和原输入，只查询／收取，不另换 ID 自动重投。明确失败的返修按已授权范围处理。
- 机器／模型变更记录独立来源，保留未采用或未完成任务，不能把不同资源的结果伪装为同一原任务。
- 新脚本创建产物前使用 `skills/shared/scripts/output_paths.py` 校验路径。成品放 `outputs/<具体主题>/`，源片、参考图、提示词、运行记录和工程素材放 `assets/`。
- 用现有 `manifest.py` 登记简报、策划与成品路径；薄索引不复制剧本全文。

## 输出

- `product-facts.json`：商品、事实来源、素材来源和核对时间。
- `brief.md`、`script.md`、`assets/storyboard.json`：本次意图与制作规格。
- `final.mp4`、`cover.jpg`、`captions.srt`：实际交付；仅在文件存在且完成相应检查后列入成品。
- `assets/`：原始片段、参考、提示词、真实回执、采用记录及可编辑工程。
- `qa.json`：实际通过项、观察、未检查项及成片摘要。
- 发布／复盘资料按任务需要追加，不生成虚假的发布成功、挂载成功或经营指标。

## Profile 感知

有画像时使用与本片有关的受众、语气、品牌风格和长期偏好；本次用户指示优先。没有画像时依据商品事实和本次简报完成，不要求先建画像。
