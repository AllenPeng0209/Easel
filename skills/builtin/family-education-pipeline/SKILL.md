# 家庭教育制作与发布

从站内 AI 对话完成一条真实案例，让创作要求、生成任务、全片、可编辑工程和发布回执能互相追溯。创意与剧本由当前对话根据本 IP 发想；已有作品只在本次获准的范围内复用。

## 按阶段读取

- 创意与定位：[家庭教育选题与转化](../family-education-strategy/SKILL.md)。先读当前 IP 的画像与已知复盘，提出少量不同方向，再确定首条及选择理由。
- 剧情与分镜：读本包的[剧情和导演验收](references/editorial-and-qa.md)，再按需要用 [AI 短剧](../short-drama/SKILL.md) 的角色、对白和连续性方法。这里只借制作方法，不把短剧批量、替换配音等默认值当成本次授权。
- H3 提示编译与声音归属：读内置 [H3 电影视听制作](../h3-cinematic-prompt/SKILL.md)，将剧本编译为英文六段式、稳定说话人 ID 与中文原词容器；方法是经验结构，不保证对白或音质。
- 生产与交接：[家庭教育成片](../family-education-film/SKILL.md)、[视频工坊](../video-workshop/SKILL.md)，以及本包的[制作计划与参考输入](references/production-plan.md)、[阶段账与工具边界](references/handoff-and-state.md)。
- 归档与发布：[素材管理](../asset-manager/SKILL.md)、[发布前完整性检查](../skill-publish-checklist/SKILL.md)。检查项按本条视频形态选择，不套用图文卡片数量或比例；真实执行走本会话提供的 Host 发布工具。

## 1. 定位这一次制作

确认运行时注入的 IP、项目根和输出根，在该 IP 新建人类可读的制作目录 `outputs/<具体项目名>/`。沿用当前会话已选择的画像、平台、账号及规格；缺少关键事实先查站内资料。

没有画像时，以本次确认的简报工作并标明假设，不复制其他 IP 的 profile 或虚构已绑定的身份、资历与账号定位。

未指定的画幅等制作规格先提出带理由的完整方案，在同一次制作确认中落实，不把普通偏好拆成多轮询问。

同名片或相近题材也用独立批次和集号，先做完整首条。参考另一工作的技能不代表获得它的 17／27 条批量额度、演员素材、账号、云端连接或重拍授权。不要为比较方法读取或复制其他 IP 的素材。

生成前明确目标：观众、可见事件、家长代价、孩子的新信息、一次有限改变、结尾动作、画幅、总时长和交付形式。没有商品或真实直播资料时采用与故事对应的评论提问或可执行建议，并记录商务信息未设置，不编造“正在直播”、老师资历或效果保证。

## 2. 先完成能拍的创意

以本次需求确定故事长度。采用已测同款方法时，约 45 秒中保留约 38 秒故事、7 秒老师回应：冲突、家长代价与反差、问题变化、有限进展、结尾回扣。它是参考节奏，不是每个家庭教育视频的硬规格；用户明确的时长和形式优先。不要为了生成接口单段上限，把完整剧情缩成 20 秒的一问一答。

编写完整对白与逐镜表，再按动作、情绪和声音单元合并为生产片段。26 个叙事镜头不等于 26 次生成；也不能把四段互不承接的片段相加，当成完整剧情。

保存简报、逐镜表、角色／声音／空间／道具连续性表和初版发布文案。画内对白写明说话者、原词、表演和实际可用时长；每次切镜有信息或情绪理由。

## 3. 把计划登记到真实工坊

写入当前 IP 的 `series.json`，按 [家庭教育成片](../family-education-film/SKILL.md) 的实际清单格式提供 `series` 和 `episodes`。每集包含 `id`、`title`、完整 `brief`、`aspectRatio` 和计划成片相对路径。

调用 `easel_workshop_delivery` 的 `plan`，使用工具返回的工坊身份。计划路径可以尚不存在，但不能创建零字节 MP4 充当成片。后续沿用这一个工程，读取实际 revision，不自行编造内部 ID。

## 4. 冻结生成范围，再执行

先读本会话的 `easel_video_generation` schema 和 `catalog`，核对真实模型、参考输入、画幅、单段时长与当前可用性。配置存在、模型名字能列出、服务有监听，不分别等于推理就绪。新 IP 的 Ref11 若返回 `profileNeedsRepair:true`，先交平台授权操作者按当前 IP 的 `repair-capabilities` 流程修复并重查；AI 不自行改配置、刷新凭据、开隧道或直接请求供应商生成。

给出本条的生成范围：模型、片段数量、各段规格、参考来源、新生成与旧片重剪的区别、允许的返修次数，以及实际资源与计费来源。`cost:unknown` 只表示目录未登记报价，不能据此宣称零成本，也不能单凭它判为新增外部采购、反复索要价格确认。用户已明确授权使用既有 PPU 自部署 H3，且本次固定范围在该授权内时直接推进，仍保留真实 Host 范围卡和额度；新增第三方收费、扩容或范围、模型、账号等实质变化时才补确认。现有算力授权不等于无限额度。

多片或参考输入必须由当前 Host 明确支持，并绑定其真实的制作批准与额度。普通问答的默认答案、超时、模型写出的 `approved` 字段或本地清单，都不是付费授权。只有单片能力时，不换会话、换 clip 或拆成多次问答绕过额度；保留计划并报告缺少的具体能力。

当前计划契约为 `plan → approve_plan → prepare → propose → submit → status → collect`，用 `plan_status` 查询原计划；准确参数见[制作计划与参考输入](references/production-plan.md)。只有本会话确实声明这些动作才执行。`approve_plan` 由 Host 展示真实制作确认卡，模型不能传入批准布尔值；批准后 `prepare` 只提供 `workshopId / clipId / planId`，从 Host 私有计划读取冻结规格，不另改 prompt、模型或参考。未知只查原任务，不清除提交意图、不换标识重购，也不用 shell 或浏览器绕过 Host 生成通道。

跨段有人物连续性时，先实际查看获准参考，再提交给模型。Ref11 不会把本地参考文件名传给模型；新计划在冻结前按每段局部 `Image 1 / Video 1 / Audio 1` 编号写清参考归属，并核对各模态输入顺序，详见[参考编号](references/production-plan.md#参考编号)。不得为补编号改动已批准或已提交的请求。保留模型原声及原片；不把静态图、循环或冻结帧当成新表演。角色、对白或口型失败按本次返修范围处理，不能用配音或无关空镜掩盖后标成通过。

## 5. 验收片段，再完成全片

按[剧情和导演验收](references/editorial-and-qa.md) 检查实际片段的表演、原词原声、口型、连续性、净画面和切点。未看、未听、未测的项目写未验，不把完整解码当成导演验收。

以实测入出点和说话时间组片，保留自然动作和呼吸，不循环、慢放或冻结来凑台词。先产出净画面母版，再以实际说出的词制作 SRT 与白字细深色描边的字幕版，保留两者。不要用提示词里的时长代替成片 ffprobe 实测。

计划片段的 `collect` 返回 `production_segment`，只作真实生成素材，不占工坊最终 deliverables，也不是可直接给发布器使用的 Chat artifact。生成片段、全片母版、压字成片分别记录。只把本集完整 master 的路径和 SHA 交给后续；“最新文件”或最后一个工坊 deliverable 不证明它是全片。多个片段的收取不代表最终渲染已完成。

成片与时间线素材真实存在且验收通过后，用同一集清单调用 `easel_workshop_delivery` 的 `deliver`，收取真实渲染输出，核对工坊播放器与可编辑时间线。时间线素材须保留这份版本的字幕与声音；不能把净片重新拼接后冒充已压字成片。只导入了完整 master 时，如实标明单段编辑粒度；字幕独立可编辑等能力须实际存在。人工已经修改的工程先读最新状态，不覆盖。

## 6. 同一版本进入内容库与发布

登记当前 IP 内容库，保存来源、采用区间和实际 QA。通过 `present` 交付实际 master，取得不可变视频的 Chat artifact ID、版本和 SHA；工坊 artifact ID 与 Chat artifact ID 分开记录，不能混用。

展示实际成片、精确标题／正文／标签和真实目标账号，落实用户要求的成片与账号确认。生成已获准不等于公开发布已获准。

调用 `easel_publish`，携带该已确认的 Chat `artifactIds`，AI 生成片显式 `aiGenerated:true`，正文清楚标注 AI 创作。核对 Host 冻结的当前 IP、稳定账号 ID、媒体 SHA、文案及公开受众，沿用同一个批准对象进入发布中心，不重复准备或执行。

已经开始执行的操作只用 `easel_publication_status` 查询原批准／操作。`submitted`、审核中、草稿、后台候选和人工填入的链接，都不能标成自动公开成功；以原操作的真实作品 ID、同账号读回和明确公开状态验收。原生 AI 声明核验失败也不能删掉声明继续发。

## 结束或停在真实断点

更新阶段账，并交付本条的工坊、实际视频、字幕、QA、不可变版本及发布结果。发布通过后复用系统写入的发布日志和日历，不重复记账。受阻时写明原任务／操作、最后验证状态和安全续接动作，保留真实成果，不把规划、半成片或模拟回执写成全流程通过。
