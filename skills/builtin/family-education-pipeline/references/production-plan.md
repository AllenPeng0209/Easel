# 制作计划与参考输入

这里记录已冻结的 Host 接口形状，不代表当前后台已经部署或实际生成、发布已经通过。先核本会话实际 schema 和 `catalog`；缺少动作时报告具体能力差距，不猜 API。升级后的新案例使用真正注册新 schema 的站内对话；已提交任务仍沿用原 Host 身份，不借换会话增加额度。

## 当前 Pika 适配（2026-11-05）

旧 7777 机切换后的模型为 `easel-ppu-pika-h3-local::pika-h3-flex-6step`，当前已设为默认 IP 与老白 IP 的默认视频模型；每次制作仍须先读实际 `catalog`，不能把本文或下面的 Ref11 示例当作当前能力证明。旧 Ref11 已停用于新生成，原任务与素材保留。

当前 Pika Host 配置为官方 6 步、`resolution:"480p"`（小写）、请求 5—15 整数秒、24 fps 与原生音频。纯文生的 `references` 用 `[]`；图生只可绑定本 IP 内一张 PNG/JPEG。此适配不接收视频或音频参考，不能照搬 Ref11 的多模态数组，也不能用 WAV 硬锁音色。继续用英文六段式场景、稳定说话者归属和 `<d>[Chinese] 原词 </d>` 组织提示词，但这些写法不保证台词、口型或声音连续性。

Pika 原生 16:9 为 832×480、9:16 为 480×832；Host 保留原片与 SHA，再规范化为 854×480 或 480×854 的交付片。请求秒数与实际帧长分别验收。模型切换不能改写旧冻结计划：后续制作通过下文的受控替换关闭旧未提交范围，沿用已消耗额度记录，在剩余授权范围内编制新片段，并取得真实 Host 新范围卡的批准。

## 当前 IP 的能力前检

1. `easel_video_generation` 传 `{"action":"catalog"}`，选当前配置中适用于这条制作的模型，并核对实际资源与计费来源。`cost:unknown` 表示目录未登记报价，不单独证明零成本或新增 API 采购。
2. 仅在实际选择 Ref11 时，它应声明 `referenceToVideo:true`、`profileNeedsRepair:false` 和 `resolutionMeaning:"local_delivery_target"`。它要求至少图片或视频参考，不能用纯音频或空参考冒充纯文生；这些要求不套用到 Pika。
3. Ref11 配置若 `profileNeedsRepair:true`，由平台授权操作者确认当前项目作用域后使用现有配置的 `repair-capabilities` 修复流程，再查目录。不能从另一 IP 复制整份配置、覆盖凭据或让 Native AI 绕到 HTTP／脚本生成；该修复动作不适用于 Pika。
4. 目录字段说明的是能力与配置。实际连接、推理状态、原片与最终媒体仍按本次真实回执和探测验收；不调用额外付费测试来证明健康。

Ref11 单段请求为 1—14 整数秒。目录声明其原生 768P：9:16 为 768×1344，16:9 为 1344×768；最终以原片实测为准。计划的 `resolution:"720p"` 表示本机交付目标，例如竖片 720×1280，不表示模型原生生成了这个尺寸。原片、`sourceMedia`、本机规范化及最终 `media` 分开留证。

已有明确授权覆盖的既有 PPU 自部署 H3 与本次固定范围，直接沿用授权推进，不因目录未登记报价反复询价；真实 Host 范围卡和片段额度仍按下述流程落实。新增第三方收费、扩容或实质范围变化才补确认，不将现有算力说成零成本或无限额度。

## 写入真实制作清单

在本项目保存 `production-plan.json`。它与给工坊建集的 `series.json` 分开：前者冻结新生成，后者关联工坊、最终 master 与编辑时间线。

| 层级 | 字段 | 内容 |
| --- | --- | --- |
| 根 | `version` | 整数 `1` |
| 根 | `title` | 本次实际制作标题 |
| 根 | `modelId` | 从实际目录选择的完整模型 ID；当前 Pika 为 `easel-ppu-pika-h3-local::pika-h3-flex-6step`，不要复用旧 Ref11 ID |
| 根 | `aspectRatio`、`resolution` | 已确认画幅和交付目标，如 `9:16`、`720p` |
| 根 | `clips` | 1—8 个固定生产片段；整计划请求时长不超过 120 秒，实际批准只覆盖本计划列出的片段 |
| 根，可选 | `supersedesPlanId` | 受控替换时填写原计划的 32 位小写十六进制 ID；不是工具参数。见下文[受控替换](#已收片后的受控计划替换) |
| 每段 | `clipId` | 本计划内唯一、稳定的片段编号 |
| 每段 | `seconds` | 请求整数秒数，遵守所选模型限制 |
| 每段 | `prompt` | 当前 AI 已写完的完整视听提示词，包含原词、说话者、表演、声音及本段参考关系 |
| 每段 | `references` | 已选择参考数组，每项只提供 `kind` 与 `path` |

`kind` 为 `image / video / audio`；`path` 相对当前 IP 的 **outputs 根**，例如 `<本项目>/assets/refs/<实际文件名>`，不带 `outputs/` 前缀，不接受绝对路径、外网 URL、其他 IP 或符号链接。所有参考在计划时已经存在，并已实际查看／试听；不要填尚未生成的未来尾帧。

Native 不自报 SHA、MIME、尺寸或时长。Host 从真实字节探测并冻结这些证据。Ref11 每段最多 9 图、3 视频、3 音频，总计最多 12 项，含声参考合计最多 3 项；单文件上限分别为图像 10 MiB、视频 50 MiB、音频 15 MiB，音视频须在 15 秒内。按该段人物和表演需要选择最少足够的参考，并说明软参考不能保证同脸、同声或精确首帧。

## 参考编号

已部署 Ref11 的各模态参考数组项只传 `data_url`，不传本地文件名或标签。新计划的 `prompt` 须按该段实际输入顺序，分别从 `Image 1`、`Video 1`、`Audio 1` 开始编号，明确每项负责的人物、服装、动作或声音；不能只靠文件名指代。冻结前核对编号与 Host 实际绑定的各模态顺序一致。

本例四段的局部映射为：

| 片段 | 图片编号与用途 | 视频编号与用途 |
| --- | --- | --- |
| G01—G03 | `Image 1`：双人图只取男孩身份；`Image 2`：母亲单人图，米色开衫主锚 | `Video 1`：母子旧片只取男孩身份与童声；`Video 2`：母亲声线 |
| G04 | `Image 1`：母亲单人图 | `Video 1`：母亲声线 |

G04 不沿用前三段的 `Image 2 / Video 2`，本例没有独立音频参考；新计划若使用音频，也在该段从 `Audio 1` 编号。编号说明仅用于冻结前的新提示词，不能改写已批准／已提交的冻结 `prompt`、替换引用身份，或换 ID 重投。

## 实际调用顺序

以下为参数形状；尖括号必须替换为本次真实返回值与文件，不能直接提交示例，也不能增加自定身份或批准字段。

```json
{"action":"plan","workshopId":"<实际工坊ID>","manifestPath":"<本项目>/production-plan.json"}
```

Host 返回本次 `planId`、`scopeHash`、固定片段与参考证据。核对范围后：

```json
{"action":"approve_plan","workshopId":"<同一工坊ID>","planId":"<实际计划ID>"}
```

这一步展示 Host 的真人制作卡。超时、默认答案或本地文件不构成批准；查询原计划使用：

```json
{"action":"plan_status","workshopId":"<同一工坊ID>","planId":"<同一计划ID>"}
```

只有真实 approved 才继续。该卡记录本次固定制作范围；沿用已覆盖该范围的授权，不重复询价。批准每个固定片段一次，不自动增加返修；原请求未知不会释放额度。

每段先从私有批准计划准备：

```json
{"action":"prepare","workshopId":"<同一工坊ID>","clipId":"<计划中的片段ID>","planId":"<同一计划ID>"}
```

不另传 prompt、模型、时长或参考。随后依序使用同一个 `workshopId / clipId` 调 `propose`、`submit`、`status`、`collect`；例如原片段查询：

```json
{"action":"status","workshopId":"<同一工坊ID>","clipId":"<同一片段ID>"}
```

这四个动作不另传 `planId`。`submit` 仅一次，状态未知只查同任务。收取回执的 `receiptType` 与 `artifact.kind` 为 `production_segment`，不是整片交付或发布身份。

## 已收片后的受控计划替换

原片已收取但对白、表演或连续性未通过，或需要改变后续冻结规格时，可使用已实现的 `supersedesPlanId`。`collected` 只证明素材已收取，不证明导演或原声验收通过；此字段也不直接授予返修或新增额度。

1. 在新制作清单**根层**填写 `supersedesPlanId`，仍用原 `plan(workshopId,manifestPath)` 和 `approve_plan(workshopId,planId)`；没有新增 replace/reset 动作。省略字段是普通计划，显式 `null`、空串或非 32 位小写十六进制 ID 会拒绝，不降级为普通计划。
2. 原计划须属于同一用户、IP、Host 会话和工坊，且为 `approved`；已 `superseded` 的原计划只支持同一个既有后继的幂等回读。跨 chat 不能直接接管原计划。
3. 原计划每个已 claimed intent 都须有 Host 私有的真实 `collected` 证据，身份与原操作／任务匹配，且源片、派生片的安全路径、存在性和 SHA 均核验。Native 不自填 `collectedClaims` 或 `supersession`。`running / unknown / failed`、成功但尚未收取等状态均不能借此重置；先查原任务并完成安全收取，不能换 ID 逃过未知提交。
4. 新 `clipId` 必须与原计划及全部祖先计划的任何片段 ID 不同，也不能占用其他私有回执。新范围明确保留哪些旧素材、新增哪些片段；原计划没有提交、或全部已 collected 时也可受控替换，不要求一定存在剩余片段。
5. `plan` 只冻结 pending 后继，不关闭旧范围。Host 将原 scope、已收片 claim 和未提交片段集合纳入新范围摘要；真实新卡批准前再次核验原媒体和证据。批准时在同一状态事务中将原计划置为 `superseded`、新计划置为 `approved`，旧未提交范围由此停止准入。
6. 旧 claimed intent、回执、原片与派生片全部保留，不释放旧提交额度。只读状态／收取仍沿用原身份；不删除审计、不手改数据库，也不因新批准重放旧生成。

省略 `supersedesPlanId` 或另开 chat 不能叠加同一用户／IP／工坊的 active 批准额度：普通 pending 可以创建，但批准时跨会话核对 active 计划。原 approved 计划已有 intent 时，即使期限已过或全部已 collected，仍须经受控替换；未启动且已过期的计划不按此保持 active。

准确依据为 [Host 清单解析与媒体核验](../../../../easel/video_generation.py)、[私有计划状态与原子决定](../../../../easel/video_production_plans.py)、[真实制作卡](../../../../web/video_generation.py)。这些约束是准入／追溯契约，不是新的机器质量认证或声音无损保证。

## 本次老白首条的准备形式

由站内 AI 根据当前 IP 和本次简报提出创意、选题与新台词。本例不提供可照抄的完整剧情，也不复用另外两项工作的批量授权。

无已绑定画像时如实标明；账号使用当前 IP 目录与用户确认的真实目标。现有可用素材为本 IP 的母子／母亲参考和合规短含声片时，先查看实际内容，再决定各段引用。没有男老师参考时，不新增人物图或把母亲冒称专家：可明确选用约 38 秒故事＋7 秒母亲自我复盘与评论提问，作为本次老师收束的替代形式，不编造直播与商品事实。

一个请求时长约 45 秒的生产分组例为：

| 固定片段 | 请求秒数 | 编排职责 |
| --- | --- | --- |
| G01 | 12 | 开场事件与冲突 |
| G02 | 13 | 家长代价、可见反差与问题变化 |
| G03 | 13 | 孩子新信息、具体回应与有限进展 |
| G04 | 7 | 母亲自我复盘、故事回扣和评论提问 |

本例为四段、自动返修额度 0、不新增人物图；这些数字必须进入本次实际方案与真人确认，不从文档自动取得授权。请求 45 秒不证明原片或成片恰好 45 秒，按真实帧数、原词原声和自然切点组片，不能截断句尾来凑数。

收取后先得到净画面母版与实际 SRT，再制作保留原声的压字片段。把与最终版本一致的片段写入 `series.json` 的 `timeline`，经 `easel_workshop_delivery deliver` 真正渲染全片；核验后 `present` 最终输出并固定 Chat artifact。只有具体素材、文案和真实账号获得发布批准后，才用 `easel_publish`，保持 `aiGenerated:true`，以严格平台公开回执结束。
