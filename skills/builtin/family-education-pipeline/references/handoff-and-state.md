# 阶段账与工具边界

制作文件在当前 IP 的 `outputs/<具体项目名>/` 内。本包规定交接语义，不定义或猜测新的 HTTP 路由、付费批准字段与工具参数；真实调用以本会话已注册 schema、Host 回执和对应技能为准。

## 一份项目，分别记录事实

| 阶段 | 保存的主要材料 | 可以据此说明的事实 |
| --- | --- | --- |
| 创意 | 简报、候选与选择理由、当前 IP 画像依据 | 已确定创意，不代表账号或素材授权已取得 |
| 分镜 | 剧本、逐镜表、角色／声音／道具连续性、发布文案草案 | 已完成可执行方案，不是成片 |
| 计划批准 | 各生产片段规格和参考、明确费用或未知项、Host 批准身份及范围 | 只在真实批准范围内可提交；本地文件不授予权限 |
| 原生生成 | 稳定 clip／request／task 身份、状态、实际输入摘要、原片和探测 | 区分排队、推理完成、本地落地与片段收取 |
| 全片 | 采用区间、净母版、SRT、字幕版、剪辑记录、真实 QA 与 master SHA | 完整成片是否实际存在和通过哪些验收 |
| 工坊 | 真实工坊 ID、编辑时间线、渲染回执与输出来源版本 | 工程与具体成片版本的对应关系 |
| 内容库与对话 | 当前 IP 素材索引、不可变 Chat artifact ID／revision／SHA | 发布选择了哪一份已经展示的内容 |
| 发布 | 精确文案和目标账号、批准 ID／payloadHash、operation ID、平台回执 | 是否草稿、已提交、待核实或已明确公开 |

用 `manifest.py` 记录各层真实产物与一句结论；完整载荷存文件。续接账可用 `pipeline-state.json`，保留实际返回身份与上游关系，不能写入凭据、签名 URL 或把本地 `approved:true` 当作 Host 批准。

## 受控工具的职责

- `easel_workshop_delivery plan`：读取当前 IP 的 `series.json`，创建／续接实际工坊。计划成片路径不要求已有文件；不要制造占位视频。
- `easel_video_generation catalog`：发现本次配置的能力；新 IP 的 Ref11 `profileNeedsRepair` 要由平台授权操作者按当前 IP 修复后重查。不能从模型名字推断推理就绪。
- `plan(workshopId,manifestPath)` 冻结当前 IP 的制作清单；`approve_plan(workshopId,planId)` 取得真实人工决定；`plan_status(workshopId,planId)` 查询原计划。准确清单、参考和动作参数见[制作计划与参考输入](production-plan.md)。
- 已批准片段 `prepare(workshopId,clipId,planId)` 从私有冻结规格读取，随后 `propose / submit / status / collect` 只沿用原 `workshopId / clipId`，不再次输入 planId、prompt 或参考。原请求未知就查询；同一真实任务的收取或只读状态恢复，不等于新的生成授权。
- 多片计划须明确每段身份、输入、输出角色、任务数和批准范围；计划片段收取为 `production_segment`，不登记为工坊最终 deliverable。只有完成组片的 master 才是最终发布对象，不能拿最后一段、最后一个 deliverable 或预测时长代替全片。
- `easel_workshop_delivery deliver`：清单中的真实全片与时间线素材存在并验收后，渲染并收取同一个工程。当前交接以传入视频构成时间线，净片中没有的字幕不会自动从另一个 master 复制过来；传入对应版本的已剪／已压字片段，或在实际支持的编辑器中建立分离字幕轨。记录实际编辑粒度，再核对渲染后全片；不宣称未实现的独立字幕编辑。渲染来源版本取真实回执，不能拿当前工程 revision 冒充旧输出来源。
- `present`：对实际 master 建立不可变 Chat artifact。记录其 ID／revision／SHA；工坊 artifact ID、资源 ID、生成 task ID 都不能代替它。
- `easel_publish`：用已确认文案、真实账号和 Chat `artifactIds` 准备精确 Host 批准。AI 片 `aiGenerated:true` 且正文标注 AI 创作；原生平台声明独立核验。
- `easel_publication_status`：查询原批准与操作，只读恢复原作品回执。不得因未知结果创建另一个发布请求。

素材管理按 [asset-manager](../../asset-manager/SKILL.md) 归档、索引和标记来源。在复制或归档后重新比对最终 SHA，使工坊、内容库、已展示视频与待发固定版本一致。

## 生成额度与引用

在执行前列明：完整成片数量、各生产片段、当前模型、画幅／时长、输入参考及来源、另购图像／配音／音乐等动作、允许的返修范围和可用报价。未报价不代表免费；已批准范围不重复询问。

跨段演员、声音或场景连续性要求必须能由实际输入方式承接。若 Host 尚无参考输入，不能用文字描述冒称已经喂入图片、视频或声音；若它只允许单片，也不能换会话、拆调用或改 clip 身份突破上限。继续完成不依赖该能力的工作，并报告具体缺口。

任务状态、付费准入与批准额度由 Host 私有状态决定。只在本地制作文件写“允许重拍”、删除回执或手改数据库，不会形成有效授权。普通问答默认、审批超时和沉默也不能作正向批准。

## 断点续接

先读阶段账，再查询对应原任务或操作。保留失败原片、原请求摘要、实际错误及已完成材料。未知不重投；新增付费、换模型、增加任务或返修，仅按当前已获准范围执行。

发布 `unknown` 无法证明是否已公开。没有原作品 ID 或明确平台证据时，不盲目重发。若操作者已经核实原尝试停在最终提交前，纠正动作仍须走 Host 提供的恢复／新批准机制，保留旧审计，不能重置旧 claim 或假写成功。

最后公开成功必须关联本次原操作、稳定真实账号与精确作品 ID，并有同账号读回和明确公开状态。上传成功、候选匹配、`submitted`、审核中、退出码 0、人工填链接、模拟审阅都分别保留，不能互相替代。

完整验收记录最终覆盖：站内 AI 采用了什么创意与技能；实际创建了哪份工程；批准了何种生成范围；用了哪些真实片段；哪份 master 通过哪些检查；用户确认了哪份内容和账号；发布中心执行的是哪个不可变版本；平台最终返回了什么证据。
