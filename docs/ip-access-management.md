# IP 项目：归属、协作与账号入口

一个 IP 项目相当于一个私有仓库。项目归创建者所有，账号、画像、内容、排期和运营数据以项目为边界。成员只获得被加入项目的权限；个人 AI 对话和发布草稿还按登录用户隔离。

## 注册、登录与项目首页

未登录时展示 Chirpiva 产品介绍和登录 / 注册表单。注册包含用户名、显示名称（选填）、密码与确认密码。密码至少 10 个字符；服务端保存密码哈希和不透明的 HttpOnly 会话，不保存明文密码。注册有来源检查、用户名唯一校验和按来源限流，注册请求不能指定管理员身份或项目角色。

新注册用户没有任何 IP，也不会自动加入其他人的项目。登录后进入项目首页，查看「全部项目 / 我拥有的 / 我参与的」。没有 IP 时直接填写第一个项目的名称和简介，创建后成为唯一 Owner 并进入工作空间。已有用户名也可以交给项目 Owner，被添加后刷新首页即可看到项目。

新安装的平台也从零项目开始。首次平台管理员仍须从服务器本机初始化；历史项目与真实历史内容会兼容保留。旧系统标识仅用于读取原有存储，不向用户呈现预设项目概念。

## 项目角色

任何已登录的有效用户都能创建自己的项目。每个项目恰有一位 Owner，其他成员是 Operator 或 Viewer：

| 能力 | Owner 所有者 | Operator 运营者 | Viewer 查看者 |
| --- | --- | --- | --- |
| 浏览 IP 内容、排期和运营记录 | ✓ | ✓ | ✓ |
| 查看本项目成员和权限说明 | ✓ | ✓ | ✓ |
| AI 对话、创作、上传与内容排期 | ✓ | ✓ | — |
| 受控发布、审核和互动处理 | ✓ | ✓ | — |
| 连接、退出或配置社交账号 | ✓ | — | — |
| 修改 IP、分配或移除成员 | ✓ | — | — |
| 查看项目权限变更记录 | ✓ | — | — |
| 转移项目所有权 | ✓ | — | — |
| 退出项目 | 先转移所有权 | ✓ | ✓ |

项目首页的「管理项目 / 查看成员」和工作空间的「项目设置与成员权限」进入同一管理面板，包含成员、权限说明、权限记录及项目信息。

Owner 添加已注册的用户，选择 Operator 或 Viewer；授权立即生效，不会发送外部消息。成员角色下拉框不提供 Owner，也不能移除或降级当前 Owner。移除成员需二次确认。

所有权转移在「项目设置」单独完成：选择一位有效的已有成员，输入项目完整名称，提交当前 Owner 标识。服务端在数据库事务内重新检查 Owner 与接收成员，原 Owner 降为 Operator，接收者成为唯一 Owner，创建者记录不变。并发或过期的转移不能生成两位 Owner，也不能让项目失去 Owner。拥有项目的用户不能被停用，必须先交接项目。

Operator、Viewer 可以在项目信息页确认退出。退出后立即失去访问权限，项目内容和账号仍保留在项目内。重新加入需要 Owner 再次添加。

旧系统多 Owner 的项目在升级时保留最早加入的有效 Owner，其余 Owner 保留为 Operator，不删除成员、账号或内容。该迁移有单独的审计记录。数据库唯一约束保证每个项目最多一位 Owner；创建、交接、停用与成员管理保证项目始终有 Owner。

## 平台管理员与执行边界

平台管理员是独立的全局权限，用来管理平台用户、重置密码、模型和本机工具；它不会自动授予未加入 IP 的内容访问权。重置密码、停用或退出会撤销旧会话。不同浏览器可分别登录不同用户，同一浏览器多个标签页会同步感知登录变更。

权限由服务端在原始 HTTP 路径检查，不能靠隐藏按钮替代。项目设置、转移、退出和权限记录不会被项目 URL 重写成其他项目的旧接口。成员变更在后续请求重新检查，流式响应与登录画面传输也检查撤权。项目创建写入失败会清理新建空间与权限记录，避免残留孤立项目。

团队成员的 AI 对话使用不带宿主文件与命令工具的兼容模型 API。模型由平台管理员配置；普通项目 Owner 不会因此获得服务器工具权限。原始视频编辑器仅向平台管理员开放，运营者通过受控制作接口处理视频。

视频画布、渲染回执和互动账号凭据都核对 IP 归属。已保存的旧画布需要重新安全连接后才能继续调用编辑运行时。独立制作运行时应保留在服务端私有网络；本次 Web 登录不替代该独立服务自身的部署边界。

手动提交、真实平台发布和模拟互动在界面中分别标记；本地权限验收不会登录或发布到真实社交平台。已提交给社交平台的操作以真实回执为准，撤权不能撤销已经完成的公开操作。
